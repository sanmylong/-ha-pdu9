# PDU-9 智能电源控制器 · Home Assistant 集成

把 UnitLink PDU-9 九路智能电源控制器接入 Home Assistant。纯本地通讯，
不经过任何云服务：UDP 2288 广播搜索设备，TCP 1002 收发控制指令。

## 功能

| 实体 | 数量 | 说明 |
|---|---|---|
| 通道开关 | 9 | CH1–CH9 单路继电器控制 |
| 场景按键 | 6 | M1–M5 对应场景 0x01–0x05，M6 为关机 |
| 当前场景 | 1 | 只读，显示设备当前处在哪个场景 |
| 场景切换中 | 1 | 设备正按固件延时逐路动作时为 on |

添加集成时会自动搜索局域网内的 PDU-9，也可以手动填 IP。设备上电后 Home Assistant
还会通过 DHCP 主动发现它，在集成页弹出「发现 PDU-9 主机」的卡片。

> **DHCP 发现对部署方式有要求。** 它依赖 HA 的 `dhcp` 组件，而后者靠嗅探 DHCP 广播
> 或对本网段做 ARP 扫描来工作。HA 跑在桥接网络的 Docker 容器里时这两条都够不着
> 局域网，DHCP 发现不会产出任何结果——这不是集成的问题。实测环境（fnOS 上的
> HA Core 容器）就属于这种情况。HA OS 或 host 网络模式下正常。
>
> 这不影响使用：添加集成时的 UDP 广播搜索走的是另一条路径，在容器里工作正常
> （只要按下面说的发子网定向广播）。

**设备换了 IP 也不用管**：PDU-9 走 DHCP，重启后地址常会变。集成连不上时会用 UDP
广播按设备 UUID 把它找回来，自动把新地址写回配置并重连（日志里会记一条
`PDU-9 的地址从 x 变成了 y`）。真机验证过 `192.168.20.32` → `192.168.20.46` 的自动恢复。
手动添加的条目没有 UUID，这种情况下仍需自己改 IP。

## 安装

### 通过 HACS（推荐）

1. HACS → 集成 → 右上角菜单 → 自定义存储库
2. 仓库填本项目地址，类别选 **Integration**
3. 在 HACS 里找到「PDU-9 智能电源控制器」并下载
4. 重启 Home Assistant
5. 设置 → 设备与服务 → 添加集成 → 搜索 `PDU-9`

### 手动安装

把 `custom_components/pdu9` 整个目录复制到 Home Assistant 配置目录下的
`custom_components/` 里，重启后同样在「添加集成」里搜索 `PDU-9`。

目录结构应为：

```
<配置目录>/custom_components/pdu9/__init__.py
                                 /manifest.json
                                 /...
```

## 要求

- Home Assistant 2024.12.0 或更高
- PDU-9 主机与 Home Assistant 在同一局域网，TCP 1002 可达

## 几个实现上的关键点

这些都是真机实测得出的结论，改代码前请先读一遍，否则很容易踩回去：

1. **设备一次只处理一条指令，不支持流水线。** 连发多条读指令、间隔 0ms 时
   只有第一条能收到响应（回收率 20%），30ms 间隔才到 100%。所以所有收发都
   串行化在一把锁里，两次发送之间强制留 50ms。

2. **控制指令没有响应帧。** 切换场景（1.1）和单路控制（1.3）发出去就完事，
   不能等 ACK。集成采用「乐观更新 + 立即补一次轮询」来纠正。

3. **场景切换期间不要下发通道指令。** 状态帧第 2 字节是切换标志，切换过程
   实测持续 14~30 秒，期间固件按内置延时逐路动作。这时插一条单路指令会和
   固件的延时序列打架，所以通道开关和场景按键在此期间会直接报错拒绝。

4. **切换场景只发一条指令。** 每个场景下 9 路的目标状态和延时都存在设备
   固件里，不要再逐路发通道指令。

5. **响应匹配不能只看功能码。** 一次请求超时后，它迟到的响应会被下一个同
   功能码的请求领走。读模式配置时用回帧里的模式号做了二次校验。

6. **UUID 要从 UDP 搜索的回复里取。** TCP 的 1.4 读 UUID 在实测设备上只
   返回 `"0"`，不可用。

7. **搜索必须发子网定向广播。** HA 默认只启用默认网卡，
   `network.async_get_ipv4_broadcast_addresses()` 在这种情况下只返回
   `255.255.255.255`；而 HA 跑在 macvlan 容器里时这个地址到不了设备。
   集成改为自己从网卡地址和掩码算出 `192.168.x.255` 这类子网广播地址。

## 协议

见《PDU-9 APP端&Can口&MQTT通讯协议.pdf》。帧格式：

```
0xAA + "JR4\0"(4B) + 参数长度(1或3B) + 参数 + 帧尾 [+ CRC16]
参数 = 操作码(1B) + 功能码(1B) + 配置数据
```

帧尾 `0xBA` 表示无校验，`0xBB` 表示其后跟 2 字节 CRC16。
CRC 为 **CRC16/XMODEM**（多项式 0x1021、初值 0x0000、无反转、无异或），
校验范围是帧头 `0xAA` 到帧尾 `0xBB` 的全部字节，**传输时低字节在前**。
